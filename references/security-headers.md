# Security headers

Load before opening, and when adding a third-party script, an iframe, a Worker, a relay or any server-side response.

## Contents

- Inline scripts: by hash only
- Cloudflare `_headers` and Workers

## Base set

On every HTML response:

```text
Content-Security-Policy: default-src 'self'; script-src 'self' 'sha256-<hash>'; connect-src 'self'; img-src 'self' data:; style-src 'self'; font-src 'self'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: camera=(), microphone=(), geolocation=()
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
```

- HSTS is set at the zone level, once the whole site works in HTTPS (see the Cloudflare reference).
- `style-src 'unsafe-inline'` is a common trade-off for inlined critical CSS: justify it in the project. Recommendation (unsourced). Keep CSS out of `style="..."` attributes so the policy can stay strict.
- Third-party services (CAPTCHA, video, fonts): add exactly their origins to `script-src`, `frame-src`, `style-src` or `font-src`, nothing more. Self-hosting fonts avoids both the third-party request and the CSP exception.
- A page that carries a token in its URL (fragment or parameter): `Referrer-Policy: no-referrer` and a stricter CSP on that path.

`check-site`: HEADERS-001 (error without `nosniff` or CSP; warning without Referrer-Policy, Permissions-Policy, framing protection, or HSTS online), CSP-001, CSP-002, HEADERS-002.

## Inline scripts: by hash only

- An unavoidable inline script is allowed by its exact hash, never by `'unsafe-inline'`, a static nonce or `'unsafe-eval'` (CSP-001).
- Moving the script to a file (`/assets/x.js`, covered by `'self'`) is often simpler.
- Hash of the exact text between `<script>` and `</script>` (whitespace counts). `check-site` prints the expected value in CSP-002; or:

```bash
node -e "const s=require('node:fs').readFileSync(0,'utf8');console.log('sha256-'+require('node:crypto').createHash('sha256').update(s).digest('base64'))" < inline.js
```

- A test compares the hash in the CSP with the script really present in the built HTML (CSP-002 does it): otherwise an edit of the script breaks the page silently.
- `application/ld+json` blocks are data, not executed: they need no hash.

## Cloudflare `_headers` and Workers

- `_headers`: at most 100 rules, 2,000 characters per line. Source: https://developers.cloudflare.com/workers/static-assets/headers/ (read 2026-10-12)
- **`_headers` does not apply to responses generated by a Worker**: "Custom headers defined in the `_headers` file are not applied to responses generated by your Worker code". Every relay, API or server-rendered response sets its own headers, with a test. Source: https://developers.cloudflare.com/workers/static-assets/headers/ (read 2026-10-12)
- A request that matches several rules "will inherit all rules' headers", and the values of a header applied twice are "joined with a comma separator": two CSP values become two policies, and the browser enforces both. Check the served result with `curl -sI` on the path. Source: https://developers.cloudflare.com/workers/static-assets/headers/ (read 2026-10-12)

## Relay template

An analytics relay served by the site (`/ingest/*` forwarded to the vendor) keeps the CSP at `'self'`, but it must:

- not forward the visitor's cookies to the vendor, and not return the vendor's `set-cookie`;
- limit methods (GET, HEAD, POST) and bound the body size;
- set its own security headers (`_headers` does not reach it);
- decide explicitly whether the visitor IP is forwarded, and configure the vendor not to keep it.

```js
const ALLOWED = new Set(['GET', 'HEAD', 'POST']);
export default {
  async fetch(request) {
    if (!ALLOWED.has(request.method)) return new Response(null, { status: 405 });
    const url = new URL(request.url);
    const upstream = new URL(url.pathname.replace(/^\/ingest/, '') || '/', UPSTREAM);
    upstream.search = url.search;
    const fwd = new Headers(request.headers);
    fwd.delete('cookie');
    const res = await fetch(upstream, { method: request.method, headers: fwd, body: request.method === 'POST' ? request.body : undefined });
    const headers = new Headers(res.headers);
    headers.delete('set-cookie');
    headers.set('X-Content-Type-Options', 'nosniff');
    headers.set('Referrer-Policy', 'strict-origin-when-cross-origin');
    return new Response(res.body, { status: res.status, headers });
  },
};
```

Check online with `check-site --url <origin> --path /ingest/<path>` (HEADERS-002) and `curl -sI`.

## Say in the report

- `_headers` does not cover responses generated by a Worker: the relay sets its own headers and strips `set-cookie`.
- Every origin added to the CSP and why; every trade-off kept (`style-src 'unsafe-inline'`), for the owner.
- What remains to check online (`curl -sI`, browser console without CSP errors).
